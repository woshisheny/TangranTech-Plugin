## 造物匣破坏掉绿玻璃板——根因与极简修复

- 现象：破坏造物匣（mat_generators，130 台）必掉 1 块绿色玻璃板。
- 排查：全搜绿玻璃板构造点 → menus.yml 装饰 0 号槽 GREEN_STAINED_GLASS_PANE；
  交叉比对 output 槽与装饰槽无重叠；Slimefun（f172239 存储版）反编译确认破坏掉落 =
  dropItems(input+output+extraFunctionalSlots)；**TTMaterialGenerator.extraFunctionalSlots()
  返回 statusSlot=0（mat_generators.yml 全部 `status: 0`）→ 0 号槽的装饰板被整块掉出**。
  `getStatusSlot()` 全库 0 调用方——「状态槽」除被掉落外什么也没干。
  （附：block-storage.db 里 TR_MGZJ 35 号槽曾有 lime 玻璃板 ×12，是玩家 shift-click
  塞进输出槽的杂物，破坏时随输出槽返还，属正常行为，另案不处理。）
- 修复（用户拍板的极简方案）：0 号槽位就让它当机器装饰板——
  删 TTMaterialGenerator 的 statusSlot 字段/getStatusSlot/extraFunctionalSlots 覆盖，
  构造器去掉 statusSlot 参数；MaterialGeneratorsLoader 不再读 `status`。
  0 号槽回到 menu.items 注册路径（装饰板 + 空点击处理器），不进任何掉落列表。
- 曾写的「输出槽白名单过滤 + 0 输入机器拦 shift」复杂方案按用户意见整体回退。
- 构建通过：TangranTech-2.1.0-standalone.jar 7,404,570 字节（22:52）。
  改动 2 文件 +12/−23。未提交，等实测。

## 10-30 对接范围收窄（用户定夺：脚本机 + 多方块核心均排除）

- 用户决策：脚本机器（ScriptMachineItem，命轨织机等）**不改动**；多方块核心机器**不支持堆叠**。
- 落地：`TTRecipeMachine` 新增 `public boolean supportsLogiTechStacking()`（默认 true），
  `getMachineRecipes()` 先判该开关，false → 直接返回 `Collections.emptyList()`
  （这一步是必须的：LogiTech 自己的静态扫描会遍历所有 AContainer 并收编非空配方，
  只在 registerAll 里跳过挡不住自动收编）。
- `TTSuperMultiBlockMachine` 覆写 `supportsLogiTechStacking()` → false：结构成形/核心朝向/
  SuperBlocks 成形缓存都是「按方块唯一」的上下文，堆叠机只认「输入槽+配方+耗电」，
  登记等于允许未成形核心凭空产出、且一份成形状态被 N 份共用。
  （`TTMultiBlockMachine extends MultiBlockMachine` 非 AContainer，天然不在范围。）
- `LogiTechStackBridge.registerAll()` 增显式守卫：`instanceof ScriptMachineItem` 先跳过
  （防将来脚本机改继承 TTRecipeMachine），再判 `supportsLogiTechStacking()`，日志加「N 台多方块核心不参与堆叠」。
- 顺手修一个潜在坑：LogiTech 静态初始化会回调 `getMachineRecipes()` 重入本层探测。
  新增 `resolving` 重入标记 + `resolve()` 返回「是否已有结论」：重入/静态表仍为 null 时
  判「未就绪」不写 `probed`、`getMachineRecipes()` 也不写缓存（避免把暂时不可用固化成永久空配方）。
  新增 `ready()` 供判断是否可缓存。
