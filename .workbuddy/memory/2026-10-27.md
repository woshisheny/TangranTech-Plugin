# 2026-10-27 工作日志

## 权限 hook LuckPerms + 玩家数据迁 SQLite + 储物空间 NBT + /tr import

用户需求四条（已确认口径）：① hook 权限插件 LuckyPerms=LuckPerms；② 信息存储改 SQLite；
③ 储物空间要能存 NBT；④ 新增 `/tr import` 从 RSC 导入玩家信息。范围选择：权限=管理侧+玩法准入、
存储=全部迁 SQLite（JSON 仅作导入源）、导入=全量+预览模式。

### 1. 依赖与打包（build.gradle.kts）
- `compileOnly("net.luckperms:api:5.4")`（运行期由 LuckPerms 提供，jar 内 net/luckperms = 0 个条目）
- `implementation("org.xerial:sqlite-jdbc:3.47.1.0")` 但 **exclude slf4j**（Paper 自带 2.x，避免遮蔽）
- jar 任务 `from(runtimeClasspath.zipTree)` 打进驱动；**只保留常见平台原生库**
  （Linux x86_64/aarch64/armv6、Linux-Musl、Windows x86/x86_64/armv7、Mac），
  排除 Android/FreeBSD/ppc64/riscv/Linux-arm/armv7/x86/Windows-aarch64 → 产物 1.4MB → **7.1MB**
- `duplicatesStrategy` INCLUDE → **EXCLUDE**（sqlite 也有 MANIFEST 等重复项）

### 2. 存储层（新增 util/Sqlite + util/Store）
- 表：`player_doc(ns, key, doc, updated_at, PK(ns,key))` + `app_meta(k,v)`；
  ns=原子目录名、key=玩家名（与原 `<玩家名>.json` 一一对应），doc=美化 JSON
- `Sqlite`：单连接 + 全局锁 + WAL/synchronous=NORMAL/busy_timeout；`jdbc:sqlite:` 路径统一把
  反斜杠换成正斜杠（Windows 服实测 `C:\...` 会被 sqlite-jdbc 误解）；打不开即降级
- `Store`：load/save/delete/exists/keys/count/updatedAt/namespaces/meta + `importLegacy`
  （返回 ImportReport：dryRun/perNs/created/overwritten/skipped/failed/samples）
- **路由点只有一个**：`AddonPaths.readJson/writeJson` —— `addon_configs/糖然科技/<一级子目录>/<名>.json`
  判成 `(ns,key)` 走库，其余（`addons/**` 资源、`.txt` 标记）走真实文件。
  另加 `docExists/deleteDoc/listDocs/docUpdatedAt`（listDocs 返回「路径形状的虚拟 File」，库里键 + 盘上未入库旧文件合并）
- 启动 `Setup.loadAll()` 最先 `Store.init()`：建表 + 首次把旧 JSON 全部导入（不覆盖已有）+ 写 `app_meta` 标记；
  单条读时库里没有也会顺手入库（惰性迁移）
- 卸载 `onDisable` → `Store.shutdown()` 关库
- 已知边界：`浮生当铺缓存.json`、语言文件、终刻合成台配方、`_head.txt` 仍在磁盘（资源/可再生缓存，非玩家数据）

### 3. 各模块文件语义改造（exists/delete/listFiles）
- AscensionPathScript：裸 `Files.readAllBytes/写入` → `AddonPaths.readJson/writeJson` + docExists
- StorageSpaceScript（3 处）、StorageSpaceUnlockScript、TwinLedger（2）、HeavenCurrencyScript、
  FinalCraftingTableScript（天道证明/存档 2 处）、QuestsScript（任务其二判定）→ docExists
- BossInventory（备份删除 + 孤儿扫描）、BossArena（deleteRecord/listRecords/自清理/旧单文件记录）→ deleteDoc/listDocs
- **FullAnalysisScript** 曾用裸 `Files.write` 直写丹方/异火/境界 —— 迁移后会写进文件而模块读库，
  已改为走 AddonPaths（这类「绕过点」最危险，审计时专挑 `Files.write`/`new File(...addon_configs)`）

### 4. 储物空间 NBT（StorageSpaceScript）
- 存档从 `{id: 数量}` 升级为「桶」：白板/旧档仍是 `"STONE": 128`；
  带数据物品是 `"STONE#<12位SHA1>": {count, nbt: base64}`（`ItemStack.serializeAsBytes()`，数量归一为 1 再算）
- 白板判定：与 `buildCleanStack(cat,id)` 的字节逐一相等 → 合并进 id 桶；否则单独成桶
- `protoOf()` 取用时反序列化还原（失败降级白板并记日志）；展示图标直接用存下来的物品
- `count/setCount/sortedKeys` 全部改用 `countOf(entry)`（原来 `asLong(Map)` 会把 NBT 桶当 0 过滤掉）
- 自动归位改成按「完整桶键」匹配（NBT 物品不会和白板同 id 混桶）

  （走 `UserManager#modifyUser`，异步落盘；没装 LuckPerms 时空操作）
- 替换的 isOp 点：BossArenaProtector（场地放行）、FinalCraftingCompilerScript（编译器准入 2 处）
- plugin.yml：`softdepend` 加 LuckPerms

## 10-27 储物/灵圃体验批（未提交，等实测）

- **写后缓存 + 5 分钟落库**：`Store.save` 不再逐条打 SQLite，先进 `PENDING`（ns\0key → JSON），
  `Store.init` 起 `runTaskTimerAsynchronously` 6000 刻一次 `flush()`，后台每次打印
  `[存储] 定时保存完成：写入 N 份文档`。`load/exists` 先查缓存（本进程即时可见）；
  `keys/count/namespaces` 与旧档导入落标记前先 flush；`shutdown` 先落库再关。
  代价：强杀进程最多丢 5 分钟进度（正常停服不丢）。
- **去掉「不要存入带 NBT 物品」提示**：`buildMainMenu` 两行 lore 删除（桶模型下已无意义）。
- **灵圃实时刷新**：`openLingpu` 起 per-player 20 刻任务 `LINGPU_REFRESH`，holder 不符/下线自动停，
  `StorageSpaceScript.shutdown()` 全停；写档走写后缓存无压力。
- **灵植事件 bug 根因**：`handleLingpuClick` 里 `cursorId = lingpuItemId(cursor); if (null) return;`
  在事件处理之前 —— 水桶/锄头/骨粉是原版物品，`slimefunIdOf` 恒 null，三类事件永远走不到。
  修法：事件材料判定提前到 id 判空之前，逻辑抽成 `handleFarmEvent(player,name,data,plot,index,slot,top,cursor,evType)`。
  另修：handleLingpuClick 原来「先 load 再 refreshLingpuMenu（内部又 load+save）」，
  点击保存会回拨刚推进的倒计时 → 调换为先 refresh 后 load。
- **取下机制**：空手右键（含蹲下右键）直接取下，返还 `buildCleanStack` 现造的灵圃+种子
  （不带灵植数据等附加 NBT），种植进度丢弃；收获改为空手左键。lore 改「右键直接取下灵圃（种植进度不会保留）」。
- 构建通过：`TangranTech-2.1.0-standalone.jar` 7.1MB（08:43），javap 确认 flush/PENDING 已进 jar。
